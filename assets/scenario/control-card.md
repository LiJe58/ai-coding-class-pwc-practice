# 거래처 계좌 변경 통제 테스트

이 문서는 Day 1 공통 실습에서 사용하는 교육용 통제 기준입니다. 회사명과 사용자명은 모두 가상이며 실제 계좌번호·사업자등록번호·연락처·이메일·서명·인감 이미지를 포함하지 않습니다. 계좌와 사업자등록번호는 마스킹된 표시값만 사용하고 자료 연결은 별도의 합성 식별자로 수행합니다.

## 통제 목적과 범위

거래처 지급계좌가 유효한 요청과 독립된 사전 승인에 근거해 ERP에 정확히 반영됐는지 확인합니다.

- 검토 대상 기간: 2026년 8월 1일~8월 30일
- 모집단: 거래처 계좌 변경 30건
- 유효 데이터: 29건
- 수행 주기: 월 1회
- 수행자: 내부통제 검토 담당자
- 결과: 정상 21건·검토 필요 8건·입력 오류 1건

증빙 미수취·추가 확인 상태와 변경 후 지급 정보는 상세 화면의 참고정보입니다. 이번 핵심 판정 건수에는 추가하지 않습니다.

## 입력자료와 연결 기준

| 자료 | 행 식별자 | 다른 자료와 연결하는 값 |
| --- | --- | --- |
| 거래처 변경 모집단 | `change_id` | `vendor_id`, `request_id`, `requested_by`, `changed_by` |
| ERP 거래처 마스터 | `vendor_id` | `current_account_token` |
| 변경 승인 기록 | `approval_id` | `change_id`, `approved_by`, `approved_account_token` |
| 증빙 등록부 | `evidence_id` | `request_id`, `document_account_token` |
| 지급 요청 | `payment_id` | `vendor_id`, `change_id`, `beneficiary_account_token` |
| 사용자 역할 | `user_id` | 요청자·승인자·변경자·확인자 ID |

행 번호·회사명·사용자명으로 자료를 연결하지 않습니다.

## 핵심 통제 규칙

### R-01 필수값과 형식

- `change_id`, `case_id`, `vendor_id`, `request_id`, `requested_by`, `changed_by`와 계좌 토큰이 있어야 합니다.
- `requested_at`, `changed_at`은 `YYYY-MM-DD HH:mm:ss`의 실제 달력·24시간 값이어야 합니다.
- `change_id`가 중복되면 안 됩니다.
- 실패한 행은 `입력 오류`로 분리하고 R-02~R-04에서 제외합니다.

### R-02 변경 전 승인

- 최종 승인 결정이 존재해야 합니다.
- `approved_at`은 `changed_at`보다 빠르거나 같아야 합니다.
- 승인 기록이 없거나 ERP 반영 후 승인되면 실패입니다.

### R-03 요청·승인 업무 분리

- `requested_by`와 최종 `approved_by`가 달라야 합니다.
- 승인 기록이 없으면 `평가 불가`로 기록하며 R-03 실패로 집계하지 않습니다.

### R-04 승인 계좌와 ERP 일치

- `approved_account_token`과 `vendor_master.current_account_token`이 같아야 합니다.
- 승인 기록이 없으면 `평가 불가`로 기록하며 R-04 실패로 집계하지 않습니다.

R-02~R-04 중 하나라도 실패하면 사례 상태는 `검토 필요`입니다. 규칙별 실패와 평가 불가 결과는 모두 사례 상세와 SQLite에 남깁니다.

## 화면과 저장 Acceptance 기준

- API와 대시보드에 전체 30·유효 29·정상 21·검토 필요 8·입력 오류 1이 표시됩니다.
- 입력 오류 1건은 유효 모집단과 R-02~R-04 실행 대상에서 제외됩니다.
- 예외 8건의 상세에 실패 규칙과 연결 승인 ID·증빙 ID가 표시됩니다.
- 승인 없는 `CHG-2608-023`의 R-03·R-04는 `평가 불가`로 표시됩니다.
- SQLite에는 고정 실행 ID 기준으로 유효 모집단 29건과 규칙별 결과가 저장됩니다.
- 같은 실행을 반복해도 같은 실행 ID의 결과를 교체하므로 중복 누적되지 않습니다.

코드는 고정된 규칙 사실만 판정합니다. MCP 증빙 조회·Agent 검토자료 초안·사람의 최종 검토 저장은 Day 1 범위에 포함하지 않습니다.
